# MUSCLE Full-Codebase Audit — 2026-06-12 (rev 2, implementation spec)

Scope: all of `src/muscle/` (188 files, ~68K lines) on branch `release-prep`, including the
uncommitted provider/cache release-prep diff. Method: six parallel subsystem reviews
(core runtime, code-review subsystem, memory/DB/learning, optimization/cost, plugin docs/TUI,
pending diff), every finding re-verified against source before being accepted, fixed, or
dismissed.

**Status at this revision:** all four quality gates green — strict mypy (188 files), ruff
lint, ruff format, full pytest suite **2929 passed / 3 skipped**. Thirteen fixes are already
landed and verified (sections A and B). Section C is the remaining work, written as
**precise change orders for an implementing agent**.

---

## How to use this document (instructions for the implementing agent)

- Each change order in section C states: files, exact change, acceptance criteria, and
  **non-regression guardrails**. The guardrails are binding: these fixes must only *add*
  safety/correctness — never remove a feature, narrow a public API, change a default the
  user can observe, or delete behavior a test encodes (update a test only where the order
  explicitly says so).
- After each order: run `uv run ruff check src/muscle/ --fix && uv run ruff format src/muscle/
  && uv run mypy src/muscle/ && uv run pytest tests/ -q` and do not proceed while red.
- Always invoke tools via `uv run` (a globally installed mypy gives false results — PKG-03).
- `timeout` does not exist on this macOS; do not wrap test commands in it.
- Work top-to-bottom: orders are sequenced so earlier ones never conflict with later ones.

## C. Change orders (remaining work, priority order)

### C1. Committee `synthesize` dedup must not merge across category/CWE — HIGH

- **File:** `src/muscle/code_review/committee_reviewer.py`, `synthesize` (~lines 495–551).
- **Problem:** the fuzzy-title bucket key is `(file_path, line_number, fuzzy_title)`. Two
  semantically different findings at the same line (e.g. SECURITY vs CORRECTNESS with similar
  titles) collapse into one, dropping the other's category/description. Project critical rule
  prescribes bucketing on `(file, line, category, cwe_id)`.
- **Change:** include `issue.category` and `(issue.cwe_id or "")` in the bucket key alongside
  the existing fields. When duplicates *do* merge (all key fields equal), keep current merge
  behavior (highest severity wins) but preserve all distinct `suggested_fix` values (join or
  list) instead of discarding.
- **Guardrails:** dedup must still collapse true duplicates from different agents (same file,
  line, category, cwe, similar title) — do not disable fuzzy-title matching, only narrow it.
  No change to the `ReviewIssue` dataclass’ public fields.
- **Acceptance:** add unit tests: (a) same line, same title words, different categories →
  two findings survive; (b) identical finding from two agents → one survives. Full suite green.

### C2. `chat_streaming` breaks on the OpenAI-compatible endpoint — HIGH

- **File:** `src/muscle/m27_client.py` (`chat_streaming`, ~lines 1040–1090).
- **Problem:** streaming hardcodes `f"{self.base_url}/v1/messages"` and
  `_apply_thinking_param(..., is_openai_compatible=False)`. With `MINIMAX_API_BASE=openai`
  (base ends `/v1`), it POSTs to `…/v1/v1/messages` → 404, with the wrong thinking shape.
- **Change (minimal, non-regressive):** detect the OpenAI-compatible base the same way
  `chat()` does. If OpenAI-compatible, raise a clear, typed error early:
  `M27ClientError("streaming is not supported on the OpenAI-compatible endpoint; unset MINIMAX_API_BASE or use chat()")`
  — or, if a sibling error type doesn't exist, `RuntimeError` with that message. Do **not**
  attempt to implement OpenAI SSE parsing in this order.
- **Guardrails:** zero change to the Anthropic-path streaming behavior (byte-identical
  request). Do not alter `_parse_sse_stream`, retry semantics, or the mid-stream-failure
  handling (Fix C2/H3 comments in file).
- **Acceptance:** unit test that constructs a client with an OpenAI-style base URL and asserts
  `chat_streaming` raises with a helpful message before any HTTP call (mock `requests`).

### C3. Transactional integrity in `project_memory.py` — HIGH

- **File:** `src/muscle/project_memory.py`.
- **Problem:** four read-modify-write paths run outside `_run_write_transaction`:
  1. `record_transferred_lesson_outcome` (~2404–2509): SELECT counts → compute → UPDATE;
     concurrent sessions lose validation events.
  2. `promote_transferred_lesson` (~2514–2613): `insert_learned_rule` commits, then a separate
     status UPDATE — crash between them re-promotes and duplicates the rule.
  3. `archive_transferred_lesson` (~2615–2699): metadata read-modify-write unguarded.
  4. `unlink_related_project` (~2101–2141): audit-log INSERT happens *after* `conn.commit()`
     of the UPDATE+DELETE — crash window with no audit row.
- **Change:** route each full sequence through `_run_write_transaction` (it already exists
  with retry/backoff). For (1), prefer a single atomic SQL increment
  (`SET validation_count = validation_count + 1, success_count = success_count + ?`) where the
  Python-side computation allows. For (4), move the `insert_action_log` body into the same
  transaction callback.
- **Guardrails:** method signatures, return values, and emitted log/audit content unchanged.
  `insert_learned_rule` is called elsewhere — do not change its standalone behavior; inside
  `promote_transferred_lesson` either inline its SQL into the transaction callback or add an
  optional `conn=None` parameter defaulting to current behavior.
- **Acceptance:** existing tests green; add a test that simulates a failure between rule
  insert and status update (monkeypatch) and asserts no duplicate rule on retry.

### C4. `SystemDatabase` concurrency pragmas — MEDIUM

- **File:** `src/muscle/system_db.py` (`_get_connection`/`_init_db`).
- **Change:** match `ProjectMemory`: `PRAGMA journal_mode=WAL` and `PRAGMA busy_timeout=5000`
  on every connection. The global `~/.muscle/system.db` sees cross-project concurrent writers.
- **Guardrails:** no schema or API change. WAL is persistent per-database — that is expected.
- **Acceptance:** suite green; quick unit test asserting the pragmas are set on a fresh connection.

### C5. `LearningIngestor.detect_and_record_recurrence` connection hygiene — MEDIUM

- **File:** `src/muscle/learning_ingestor.py` (~450–492).
- **Problem:** calls private `self._pm._get_connection()` with a manual `close()` and no
  try/finally — leaks on exception.
- **Change:** use the public `ProjectMemory` context-manager/query API if one fits; otherwise
  wrap in `try/finally` (or `contextlib.closing`). Keep the SQL identical.
- **Guardrails:** identical query results and recurrence-recording behavior.

### C6. `CostOptimizer` cache: hold the lock for whole multi-statement operations — MEDIUM

- **File:** `src/muscle/cost_optimizer.py` (~197–334).
- **Problem:** `_get_connection` locks only connection creation; `save_to_cache`’s
  count→evict→insert and `get_from_cache`’s UPDATE→SELECT run unlocked (TOCTOU under threads).
- **Change:** hold `self._conn_lock` for the full body of `get_from_cache`, `save_to_cache`,
  and `clear_cache`.
- **Guardrails:** keep the eviction hysteresis formula exactly as is (`count - MAX + 100`);
  no behavioral change beyond atomicity. Watch for re-entrancy (none expected — verify no
  method calls another while holding the lock; if so use `threading.RLock`).

### C7. `claude_publisher` consolidation-audit append under lock — MEDIUM

- **File:** `src/muscle/claude_publisher.py` (~350–365).
- **Change:** wrap the JSONL append in the same `advisory_file_lock` sentinel pattern used by
  the host-doc write path in this file (lock file next to the JSONL).
- **Guardrails:** appended record content/format unchanged; never let a lock failure block the
  publish itself — on lock acquisition error, log a warning and still append (current
  durability is the floor, not the ceiling).

### C8. Importer: separate cache reads from cache writes — MEDIUM

- **File:** `src/muscle/optimization/importers.py` (`_import_claude_file`, ~267–269).
- **Problem:** `cache_read_input_tokens` (discounted) and `cache_creation_input_tokens`
  (1.25× surcharge) are summed into one `cache_tokens` figure; the Codex importer is correct.
- **Change:** count only `cache_read_input_tokens` in the existing cache-savings field, and
  add a **new, additional** field (e.g. `cache_creation_tokens`) carried through the imported
  record for the write-side tokens.
- **Guardrails:** additive only — keep existing field names so downstream consumers and tests
  keep working; no change to `_import_codex_file`.
- **Acceptance:** update/extend importer tests for a usage payload containing both values.

### C9. `muscle provider use --project` dead flag + first-run UX — MEDIUM

  `test_cli_provider.py` tests must pass unmodified except where they assert the old bare

### C12. `BudgetManager.check_budget` reserve/commit semantics — LOW (needs care)

- **Problem:** `check_budget` decrements `fixed_limit` on every call, so speculative

- **Change:** split into `can_afford(cost) -> bool` (pure) and `consume(cost)` (mutating);

  caller before switching it).
- **Guardrails:** this is behavior-sensitive — do not change any existing caller's observable
  budget arithmetic unless the call is provably a speculative check. When in doubt, leave the
  caller on `check_budget`.

## D. Feature effectiveness assessment (unchanged from rev 1, updated where fixed)

- **`muscle review` + learning pipeline** (flagship): architecture sound — committee review
  with deterministic + semantic passes (now always combined, after B12), verify-before-learn,
  DB-first learning storage, two-phase publisher with crash reconciliation.
- **Provider abstraction (release-prep diff)**: release-candidate quality; remaining nits are
  C9 (dead flag / first-run UX).
- **Cost/delegation accounting**: pricing tables verified against documented rates (M3
  $0.60/$2.40 ≤512K doubling above; Fable 5 $10/$50; Opus 4.8 $5/$25; tier boundary strict
  `>` matches "≤512K"). With A1 + B13 landed, reports neither fabricate unknown-provider
  spend nor overstate M3 cost.
- **Security posture**: strong — prompt-injection envelopes, single-choke-point secret
  redaction, path containment, hash-verified KB fetches, fail-closed base-URL guard. Gaps
  found were narrow; the KB URL one is fixed (A7), scrubber breadth is C13.4.
- **TUI**: functional for review history; Projects/Memory views partially placeholder
  (C13.6), consistent with `docs/architecture.md`'s own caveats.

## E. Strengths worth keeping

- Consistent atomic-write discipline via `io_safety` (now including long-eval reports).
- Careful client code: `_parse_retry_after` robustness, SSE mid-stream-failure handling,
  truncation signaling for structured calls.
- Two-phase publish with staged revisions + crash reconciliation in `claude_publisher`.

  benchmark runner; lazy `__getattr__` facade in `code_review/__init__`.
